# Schema Synchronization Complete

## Date: January 28, 2026

All changes made to iOS apps today have been synchronized with the admin portal to ensure data consistency.

---

## 1. Class Registration Schema Change

### Issue
Participant documents were using userId as the document ID, preventing multiple registrations by the same user.

### Solution
**Backend (Cloud Functions):**
- Participants now use auto-generated document IDs
- Store `userId` as a field in the participant document
- Path: `classes/{classId}/participants/{autoGeneratedId}`

**iOS App:**
- Updated `loadMyRegisteredClasses()` to query by `userId` field
- Updated `isRegistered()` to query by `userId` field
- Changed from `.document(uid).getDocument()` to `.whereField("userId", isEqualTo: uid)`

**Admin Portal:**
- Added participants viewer with Eye icon on classes page
- Queries participants by subcollection (matches new schema)
- Shows participant list with names, registration time, and count

### Files Changed
- iOS: `Skedence/Skedence/ClassesService.swift`
- Backend: `SkedenceAdmin/functions/src/index.ts` (already had correct schema)
- Admin Portal: `admin-portal/src/app/classes/page.tsx`

## 2. Recurring Classes

### Implementation
**iOS App:**
- Classes support `isRecurring` and `recurringPattern` fields
- AdminService creates recurring instances on the backend
- Each recurring instance is a separate class document

**Admin Portal:**
- Updated class creation to generate 12 weeks of recurring instances when `isRecurring=true`
- Creates trainer schedule slots for each instance to block off time
- Displays recurring badge on class cards

### Schema
```typescript
{

  recurringPattern?: 'weekly'; // Currently only weekly supported
}
```

### Files Changed

## 4. Schedule Display Fix

### Issue
Registered classes weren't appearing in user's schedule view.

### Root Cause
`MyUpcomingLessonsView` was creating its own `ClassesService` instance instead of using the shared instance.

### Solution
- Changed `@StateObject` to `@ObservedObject` in MyUpcomingLessonsView
- Pass shared `classesService` from ProfileView
- Both views now use same instance that updates after registration

### Files Changed
- iOS: `Skedence/MyUpcomingLessonsView.swift`
- iOS: `Skedence/Skedence/ProfileView.swift`

## Data Flow

### Class Registration (Client → Backend → Display)
1. Client taps "Register" with a class pass
2. iOS calls `registerForClassWithPass(classId, classPassPackageId, orgId)`
3. Cloud Function creates participant document with auto-generated ID
4. iOS reloads registered classes using `whereField("userId")`
5. Classes appear in schedule and show "You're Registered" badge

### Recurring Class Creation (Admin Portal)
1. Admin creates class with isRecurring=true
2. Admin portal generates 12 class instances (1 per week)
3. Each instance creates a trainer schedule slot
4. iOS app loads all class instances and displays them
5. Users can register for any future instance

### Package Display (iOS & Admin Portal)
1. Load all packages for user from `organizations/{orgId}/users/{userId}/packages`
2. Group by `packageType` field
3. Sum `remainingLessons` for same type
4. Display as single entry with total count

## Schema Reference

### Participant Document
```typescript
classes/{classId}/participants/{autoGeneratedId}
{
  userId: string;           // User who registered
  firstName: string;
  lastName: string;
  registeredAt: Timestamp;
  classPassPackageId?: string;  // Package used for registration
}
```

### Class Document
```typescript
classes/{classId}
{
  orgId: string;
  title: string;
  description: string;
  trainerId: string;
  trainerName: string;
  startTime: Timestamp;
  endTime: Timestamp;
  location: string;
  maxParticipants: number;
  currentParticipants: number;
  isOpenForRegistration: boolean;
  createdBy: string;
  createdAt: Timestamp;
  priceInCents: number;
  isRecurring: boolean;
  recurringPattern?: string;
}
```

### Package Document
```typescript
organizations/{orgId}/users/{userId}/packages/{packageId}
{
  packageName: string;
  packageType: string;        // Used for grouping
  packageCategory: string;    // 'pass' or 'class'
  totalLessons: number;
  lessonsUsed: number;
  expirationDate: Timestamp;
  purchaseDate: Timestamp;
  // ... other fields
}
```
